****************************************************************************************************
  Calendarはもう古い！
****************************************************************************************************

  DateはJava1.0
  CalendarはJava1.1

  Java1.8以降は以下のクラスを使う
  java.time.LocalDateTime
  java.time.format.DateTimeFormatter

  使い方は以下の通り。

  //now()で現在時刻のLocalDateTimeインスタンスを得る。値は不変。スレッドセーフ。getメソッドで各値を得る。
      LocalDateTime ldt = LocalDateTime.now();
      System.out.printf("%4d年%2d月%2d日%2d時%2d分%2d秒\n", ldt.getYear(), ldt.getMonthValue(), ldt.getDayOfMonth(), ldt.getHour(), ldt.getMinute(), ldt.getSecond());

  //年月日時分秒を指定する場合はof()を使う。ナノ秒まで指定できる。
      ldt = LocalDateTime.of(2024, 5, 17, 13, 19, 23, 123456789);

  //フォーマッタの使い方
  //SQLで日付を扱うときは、これを使ってStringで変換すれば良いだろう
      DateTimeFormatter dtf = DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");

  //LocalDateTime → String
      String result = ldt.format(dtf);
      System.out.println(result);

  //String → LocalDateTime
      ldt = LocalDateTime.parse("2030-05-31 18:20:35", dtf);
      System.out.println(ldt);

  //他に、LocalDateやZonedDateTimeなどのクラスがある

  //比較はcompareTo()。equals()も使える。
  //よく見たら、isAfter()とisBefore()もあった。
      LocalDate d1 = LocalDate.of(2024, 5, 27);
      LocalDate d2 = LocalDate.of(2024, 5, 28);
      System.out.println(d1.compareTo(d2));     //-1
      System.out.println(d2.compareTo(d1));     // 1

  //ZonedDateTimeの使い方。ZoneId.of("")でタイムゾーンを指定する。
  //世界標準時 → Z, GMT, UTC
  //ローカルタイム → +9, GMT+9, UTC+9 ※JSTは使えなかった。
      ZonedDateTime zdt = ZonedDateTime.now(ZoneId.of("UTC"));
      System.out.println(zdt.format(dtf));

****************************************************************************************************
  OderDAOからItemDAOへの直接アクセスはやめよう
****************************************************************************************************

  やっぱりパフォーマンスは非常に良くないし。

  OderDAOでコネクションしている上に、さらにItemDAOがコネクションするので、
  コネクションが二重となる。

  context.xmlでmaxTotal="1"にしていると、ItemDAOがコネクション出来ずに
  コネクションタイムアウトになる。

  素直にINNER JOINで商品名と単価を得るのが良いね。

  クラス図も変えなきゃか・・・

****************************************************************************************************
  注文システムに業務システムのjarを使える条件を明記せよ！
****************************************************************************************************

  業務システムのclassをそのまま利用できるのは、
  URLマッピングをweb.xmlでやってるときだけ。

  @WebServletを使っている場合は、注文システムでサーブレットを再利用するときに
  URLマッピングを書き換えて、コンパイルし直しが必要。

  だから、jarでいけるよ！という記載には、web.xmlでURLマッピングをしている場合、と
  明記しよう。
